# 安装与部署指南

[返回首页](../README.md)

第一次使用，建议按顺序完成：**打开阅读器网页 → 试读一份 PDF → 按需安装扩展**。不需要自动接管 PDF 时，可以跳过扩展安装。

## 1. 获得一个阅读器网址

### 推荐：使用已构建的网站包

这条路径不需要 Git、Node.js、编译工具或服务器后端。

1. 打开 [Releases](https://github.com/Silhouette-my/pagenest-pdf/releases/latest)。下载名称含 `site` 的 ZIP；不要选含 `extension` 的包，也不要选 GitHub 自动生成的 **Source code** 包。
2. 解压，找到直接含 `index.html` 和 `assets/` 的文件夹。
3. 登录支持静态站点上传的平台，例如 [Netlify Drop](https://app.netlify.com/drop)。将上一步文件夹拖入上传区，按平台提示部署。
4. 等待部署完成，打开平台提供的 HTTPS 地址。能看到阅读器首页后，选择一份本地 PDF，确认页面和文字正常显示。

建议让 `index.html` 位于网站根路径，例如 `https://your-site.example/`。这里的示例域名不是已上线的阅读器地址，请使用平台实际提供的网址。自有服务器也可以：将该文件夹的**内容**放入 HTTPS 网站根目录，保持 `assets/` 等目录结构完整。

网站包中已经包含 PDF.js 和 worker，不需要再接入 CDN。只需静态文件托管，没有数据库、PDF 上传服务或 API 密钥。不要双击 `index.html` 作为安装方法；`file://` 不属于这里推荐的运行环境。

### 备选：运行本地开发服务

安装 [Node.js LTS](https://nodejs.org/)，要求 Node.js 20.19+ 或 22.12+。安装程序通常同时提供 npm。

有 Git 时，在终端执行：

```sh
git clone https://github.com/Silhouette-my/pagenest-pdf.git
cd pagenest-pdf
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

没有 Git 时：下载仓库 **Code → Download ZIP**，解压，在解压后的项目文件夹打开终端，执行 `npm ci` 和最后一条启动命令。

打开终端输出的网址。若 5173 端口被占用，Vite 可能换用另一个端口，请以输出为准，并把同一地址填写到扩展设置中。

服务需要持续运行。按 **Ctrl+C** 可以停止；下次使用时进入项目文件夹，再运行启动命令，不必每次重新下载和安装依赖。本地 HTTP 服务用于试用和开发；需要验证 Gemini in Chrome 时，部署到普通 HTTPS 网页。

## 2. 安装可选的 Chrome 扩展

扩展负责把 PDF 交给你在第 1 步准备的阅读器网页。

1. 下载 Releases 中名称含 `extension` 的 ZIP，并解压到你准备长期保留的位置。
2. 在 Chrome 地址栏输入 `chrome://extensions`。
3. 开启右上角**开发者模式**。
4. 点击**加载已解压的扩展程序**，选择直接含 `manifest.json` 的文件夹。不能选择 ZIP 文件，也不要选择它的外层父目录。
5. 在扩展列表或 Chrome 工具栏中打开 PageNest PDF 的**设置**。
6. 在**阅读器网址**中填入第 1 步实际可访问的完整地址，并保存：部署时使用 `https://…/`；本地试用通常为 `http://127.0.0.1:5173/`。
7. 需要本地 PDF 自动接管时，在扩展的**详细信息**中开启**允许访问文件网址**；扩展设置中的**自动打开本地 PDF**也应开启。

如果从源码安装，直接选择仓库里的 `extension/` 文件夹即可，无需单独构建扩展。

Chrome 加载的是这个文件夹，安装后不要删除或移动它。如果移动了，请移除扩展后从新位置重新加载。扩展当前通过开发者模式安装，尚未在 Chrome 商店发布。

### 两个自动打开选项

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| 自动打开本地 PDF | 开启 | 接管 Chrome 中打开的本地 `file://` PDF，需要文件网址权限 |
| 自动接管网页 PDF | 关闭 | 开启后接管网站上的 PDF；关闭时仍可点击“打开当前 PDF” |

macOS 上本地 PDF 可能在新的阅读器标签页中打开，这是现有接管方式。扩展从远程 PDF 的原网址获取文件，再传给浏览器内的阅读器；没有把 PDF 上传到 PageNest PDF 后端。

## 3. 确认安装成功

- 网页：打开阅读器网址，选择本地 PDF，确认能翻页和选择文字。
- 恢复：阅读几页后刷新，确认页码恢复。缓存或原文件权限不可用时，可能需要重新选择文件。
- 本地接管：将本地 PDF 拖入 Chrome，确认扩展将它交给阅读器；不成功时先检查文件网址权限。
- 网页接管：打开远程 PDF，点击扩展的**打开当前 PDF**。只有开启自动接管选项后，才应期待自动跳转。
- Gemini：在部署后的 HTTPS 阅读器页面中，主动向 Gemini in Chrome 分享当前标签页，测试已渲染页面的文字。该能力还取决于 Chrome、地区及账号可用性。

实际电脑睡眠唤醒、完全退出 Chrome 后重新启动，以及 Gemini 回答，仍需要使用你的浏览器环境手动检查。自动化测试结果见[验证记录](verification.md)。

## 4. 更新网站或扩展

**网站：**下载新的 `site` 包，重新上传到同一个站点，尽量保持原网址。阅读记录属于网址的 origin（协议、域名和端口）及 Chrome 用户配置；更换 origin 不会自动搬迁历史数据。

**扩展：**下载新包，用新文件替换原安装文件夹里的扩展文件，然后到 `chrome://extensions` 点击该扩展的**重新加载**。若换了文件夹位置，需要重新加载已解压的扩展程序，并检查设置与文件访问权限。

**源码：**保存自己的修改后，在项目目录运行 `git pull --ff-only` 和 `npm ci`，再重启本地服务。自行部署前运行 `npm run check`，上传新生成的 `dist/` 内容。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| `npm` 找不到或构建提示 Node 版本过低 | 安装受支持的 Node.js LTS，重新打开终端 |
| 扩展无法加载，提示找不到清单 | 是否已解压，选择的目录是否直接含 `manifest.json` |
| 扩展打开空白页或网址无法访问 | 阅读器网址是否正确；本地服务是否仍在运行 |
| 本地 PDF 没有自动打开 | “允许访问文件网址”和“自动打开本地 PDF”是否都开启 |
| 网页 PDF 没有自动接管 | 此选项默认关闭；可以先点击“打开当前 PDF” |
| 网站部署后空白或资源 404 | 是否上传了网站包全部内容，`index.html` 是否在网站根路径，是否保留 `assets/` |
| 使用 GitHub Pages 的 `/pagenest-pdf/` 子路径 | 普通网站包按根路径构建；从源码运行 `npm run build -- --base=/pagenest-pdf/`，再部署 `dist/`，并按 Pages 的要求配置发布 |
| 刷新后要求重新选择 PDF | 缓存、文件句柄权限、文件大小上限或站点数据可能影响恢复 |
| Gemini 无法读取 | 确认是普通 HTTPS 阅读器页面，已主动分享标签页，PDF 有可选择文字，目标页面已渲染 |
